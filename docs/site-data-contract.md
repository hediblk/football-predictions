# Published site data contract

Implemented by the shared [JSON schema](../schemas/site/data.schema.json), [validator](../scripts/validate_site_data.py), and [exporter/contract tests](../tests/test_site_contract.py). [ADR 0001](adr/0001-site-model-boundary.md) records the boundary decision and [ADR 0002](adr/0002-site-browser-checks.md) the browser checks. [Numerical protection](numerical-protection.md) covers forecasting behavior before export.

Run `python scripts/validate_site_data.py --data site/data` to validate the current site. For a staged dataset, pass `--data <candidate-directory> --site site` so crest references resolve against the real site assets. Failures exit nonzero and identify the affected file or field. Run the focused tests with `PYTHONDONTWRITEBYTECODE=1 python -m pytest -q tests/test_site_contract.py tests/test_refresh_site.py`.

## Boundary and guarantees

`scripts/build_site_data.py` converts model outputs to the JSON consumed by the static site. Validate this conversion independently of model tests: a correct model can still be exported with a missing field, reversed tuple, incorrect unit, or inconsistent index. Validate the complete final dataset again before publication, including retained files and historical seasons.

Machine-readable schemas should be the authority for required fields, types, nullability, and tuple shapes. This document is the authority for football meanings, units, consistency rules, and compatibility policy. Use a small shared validator for relationships schemas cannot express. A new JSON family needs an explicit schema mapping before publication; avoid one schema copied for every competition.

Contract validation guarantees that published data conforms to these rules. It cannot guarantee JavaScript imports, rendering, interactions, or layout; the [browser checks](adr/0002-site-browser-checks.md) load every view from the same data, and layout still receives manual review.

## File families

| Path | Structure and required meaning |
| --- | --- |
| `index.json` | Nonempty competition array, currently six distinct slugs. Entries contain `slug, code, name, country, season, generated_at`, matching the corresponding published competition file. Index order is not a display-order contract. |
| `<competition>.json`, domestic | Common metadata; `kind: league`; zones and nonempty teams. Each team has identity, current position/played/points/goal difference, expected final points/position, point quantiles, position probabilities, title chance, and declared zone chances. Fixture-adjustment notes may be absent in older data. |
| `champions-league.json` | Common metadata; `kind: ucl`; 36 teams with canonical `key`, league-phase position probabilities, `r16, playoff, out`, progression `stages`, and the representative `bracket`. |
| `matches/<competition>.json` | `slug, generated_at, rule, matches`. `rule` can be null. Fixtures carry `id, kickoff, status, md, home, away, home_id, away_id`, with conditional scores, forecasts, xG, and stakes. A present UCL fixture file must not have an empty list: its round view requires fixtures. |
| `notes/<competition>.json` | `generated_at, as_of, first_season, seasons, fixtures`; each fixture has `pre, post, meetings`. Notes are fixed-template `{kind, text}` facts; the result season list documents actual source coverage. Each note list contains at most four notes for each side. |
| `scorecard.json` | `generated_at, competitions, all`; current-season scores, baseline coverage, ten calibration bins and cumulative Monday-week series. Competition entries retain their own `season` and `generated_at` on failed refreshes. See Scorecard below. |
| `clubs.json` | `generated_at, season, scale, league_averages, featured, clubs`; nonempty ranked clubs with identity, domestic league, UCL participation, ratings, expected goals against the reference opponent, and overall/attack/defense/domestic ranks. Champions League clubs from outside the five leagues have a null `league` and `league_rank`, with `country` and a three-letter `country_code`. |
| `squads/<season>/<slug>.json` | Optional per-club squad reference: identity, generation/baseline provenance, EA vintage and source hashes, roster observation, coverage, players and ideal XI. See Squad references below. |
| `crests.json` | Object keyed by decimal-string provider IDs. Entries contain `name, source, path`, with dimensions for PNGs. Published crest paths refer to local site assets. A missing crest entry leaves the club name usable. |
| `history/<season>/<competition>.json` | `slug, season, metrics, dates, cutoff, teams`. Each team has one series per metric, with entries aligned to `dates`. Domestic metrics are `title,ucl,releg`; UCL metrics are `top8,top24,last16,qf,sf,final,title`. |
| `history/<season>/clubs.json` | `season, fields, weeks`; each week has a Monday `date`, nullable result `cutoff`, and club-ID-string keys mapped to rating tuples. `fields` is currently `rating,attack,defense`. |
| `history/<season>/ratings/<YYYY-MM>.json` | `season, month, fields, runs`; one file per UTC month of the run's forecast origin. Each run has `as_of`, nullable result `cutoff`, `leagues` (the five league averages, keyed by league slug, as in that run's `clubs.json`) and club-ID-string keys mapped to rating tuples in `fields` order. Append-only; a missing month means no runs were saved then. |
| `history/<season>/forecasts/<competition>.json` | `slug, season, fixtures`, keyed by positive decimal-string fixture IDs. Receipts contain `kickoff, generated_at, p, exp, top, call, btts, o25` and optional `stakes`, copied at published precision. Missing files or receipts mean no published forecast was saved. |
| `match/<season>/<competition>/<fixture id>.json` | Per-match detail, loaded on demand by the match page (Understat feeds "Chances", ESPN feeds "Match stats" and timeline markers; UEFA adds running rows and "Where they played" for Champions League). Required envelope: `id, competition, kickoff, sources`; `competition` is the route slug and the season directory is its start year. `shots, players, retro, box, events, physical, heat, positions` are optional; missing files or keys mean that source is unavailable. Sources share this file and preserve each other's keys. |

Common competition metadata is `slug, kind, code, name, country, season, generated_at, as_of, data_cutoff, n_sim, played_fixtures, remaining_fixtures`. Zone entries contain `key, label, from, to`, with inclusive one-based position bounds.

Required current competition tables, index, and club rankings must exist and be nonempty. Match files, histories, and crests have existing missing-data fallbacks; absence is allowed where that fallback applies. A present file must be well-formed: optional availability is not permission to publish malformed JSON. Historical files can be empty during initialization where their consumers allow it.

## Units, ordering, and field meanings

| Field | Meaning and unit |
| --- | --- |
| Team `probs[i]` | Chance of finishing in position `i + 1`, percent on 0–100 scale |
| Team `position` | Current table position; separate from the projected ordering of `teams` |
| Domestic `title, ucl, europe, releg` | Chances of finishing in their declared positions, percent; these are position bands, not guaranteed sporting qualification/relegation |
| UCL `r16` | Top-eight league-phase finish and direct entry to the last 16, percent |
| UCL `playoff, out` | League-phase places 9–24 and 25–36 respectively, percent |
| UCL `stages.round16` | Reaches the last 16, including playoff winners, percent |
| Other UCL stages, `title`, bracket `advance` | Progression/winner chances, percent; bracket advancement covers the entire tie |
| Match `p` | `[home win, draw, away win]`, each on 0–1 scale |
| Match-note `meetings[].score` | `[home goals, away goals]`; `date` is the UTC match date and `venue` is the home club |
| Match `score, xg, exp` | `[home, away]` goals, observed xG, or expected goals respectively |
| Match `top` / `call` | Tuples `[home goals, away goals, probability]`, probability on 0–1 scale; `top` ordered by descending probability |
| Match `btts, o25, p_score` | Both-teams-score, over-2.5-goals, and observed-score probabilities on 0–1 scale |
| Stakes `n` and each metric array | `[match home win, draw, match away win]`; `n` is simulation counts and metric entries are percentages or null. Domestic metrics are `title, ucl, releg` (as in the table); UCL metrics are `top8, top24` (league-phase places 1–8 and 1–24) and `title` (wins the trophy) |
| Club rating fields | `rating, attack, defense, home, away, league_rating` on a 0–100 expected-points-share scale; these are not title chances |
| Club `gf, ga` | Expected goals against the reference opponent |
| Weekly club tuple, rating-run club tuple | Rating values in `fields` order, currently `[rating, attack, defense]`, one decimal |
| Rating-run `leagues` | Mean overall rating of each league's ranked clubs, one decimal, on the same scale; a league-wide shift (for example new market prices for its level) moves every club in it |
| Fixture-note `score` | Human-readable string or null, unlike a match's integer score pair |
| Match-detail `sources.understat` | `{id, fetched_at}`: positive integer Understat match ID and timezone-qualified retrieval timestamp |
| Match-detail `sources.uefa` | `{id, fetched_at, score}`: positive integer UEFA match ID, latest retrieval timestamp of the four contributing payloads, and checked final `[home, away]` score. Champions League only; post-match provenance, never a forecast input. |
| Match-detail `physical` | `{h, a}` team objects with `distance` in km, integer `sprints`, `top_speed` in km/h, and `players` rows `{id, player, minutes, distance, top_speed}`. IDs are UEFA player IDs; minutes are elapsed `TotalSeconds / 60`, rounded to one decimal, including stoppage time. Only players with positive playing time are included. Distances and speeds retain three decimals. |
| Match-detail `heat` | `{h, a}` objects, each with `team` (294 nonnegative integer activity counts) and `players` rows `{id, grid}` with the same grid for each player who played at least 30 minutes. UEFA's comma-separated 105×69 player heatmaps have x varying fastest; blank cells mean zero. Sum every participating player's map for the team, including players below 30 minutes. Downsample by summing 5×5 blocks to 21×14, with four source rows in the last y bin; totals are preserved. Flatten row-major from top left. Counts are activity samples, not touches or possession. The UI smooths the saved grid by bilinear interpolation for display, then maps relative activity from green (less) through yellow to red (more), with the scale set by that selected map's busiest cell. Captions, third-by-third totals and hover shares use the original counts; the published integers remain unchanged. Home attacks right, away left; maps retain UEFA's common pitch orientation. |
| Match-detail `positions` | `{h, a}` arrays, at most eleven rows `{id, player, number, x, y}`, for starters identified by UEFA's lineup `field`. `number` is the match shirt number. Average locations come from player statistics, not lineup formation coordinates: UEFA's centred centimetres become top-left fractions `x = (raw_x / 100 + 52.5) / 105`, `y = (34.5 - raw_y / 100) / 69`, rounded to four decimals on 0–1. |
| Match-detail `sources.espn` | `{id, fetched_at, score}`: positive integer ESPN event ID, timezone-qualified summary retrieval timestamp, and ESPN's checked final `[home, away]` score. This is post-match provenance, never a forecast input. |
| Match-detail `box` | Optional paired `[home, away]` statistics: `possession, shots, shots_on_target, corners, fouls, offsides, saves, pass_accuracy, yellow, red`. Possession and pass accuracy are percentages on 0–100; the other values are nonnegative integer counts. Pass accuracy is `100 × accuratePasses / totalPasses`, rounded to one decimal, because ESPN's `passPct` is heavily rounded. A row is omitted unless both sides have it; missing is never zero. |
| Match-detail `events` | Minute-ordered objects `{minute, clock, type, side, players}`. `minute` is the displayed minute including added time (`45+2` → 47); `clock` preserves the base and added minutes as a string. Types: `goal, own_goal, penalty_goal, missed_penalty, yellow, red, substitution`. `side` (`h`/`a`) is the participating player's team, including for own goals; own goals count for the opposite team. `players` lists names, with scorer then assister for goals and player on then player off for substitutions, when supplied. Second yellows are red events. Shootouts and extra-time events are excluded: site forecasts cover 90 minutes. |
| Match-detail `shots` | Tuples `[minute, side, x, y, xg, result, situation, body, player, assister]`, ordered by minute. `side` is `h` or `a`; minutes are Understat's zero-based elapsed minutes, including stoppage time. Coordinates are Understat's unmodified 0–1 pitch fractions, with `x` toward the attacking goal and `y` across the pitch. Shot xG is on 0–1; result/situation/body retain provider labels; player/assister are names, with null for no assister. |
| Match-detail `players` | `{h, a}` arrays of rows: `id` (Understat player ID), `player` (name), `minutes, position, shots, goals, own_goals, xg, xa, key_passes, yellow, red`. Goals exclude own goals; own goals count against the player's side. `xg` and `xa` are observed expected goals/assists, not pre-match model rates. Cards are counts. |
| Match-detail `retro` | `[home win, draw, away win]`, on 0–1. After-the-fact chances from the exact convolution of independent Bernoulli trials with each side's observed shot xGs. This assumes shots are independent, including successive attempts in the same attack; own goals are excluded. These are not pre-match forecasts and never feed the model. |

Stakes always use the fixture's home/draw/away order, including for affected clubs that are not playing in that fixture. Null means insufficient conditioning simulations, not zero chance. UCL match scores and match forecasts cover 90 minutes; tournament progression also accounts for the remainder of a tie.

The representative UCL bracket is illustrative. Its champion need not have the largest unconditional title probability. `call` is a score within the most likely outcome; it need not equal `top[0]` or appear among the listed `top` scores. The listed top score probabilities are a subset and must not be required to sum to one.

## Missing values, identifiers, and time

- Provider club IDs in tables, clubs, and match sides can be positive integers or null. Nonnull team IDs are unique within each table or club ranking, and fixture `id` values are unique within each match file. Club `home_id`/`away_id` values naturally repeat across fixtures, and the same club appearing in domestic and UCL tables is expected. Route slugs must be unique in their routing scope.
- Competition history uses a numeric club ID, or the club slug when the ID is unavailable. Weekly club history contains numeric provider IDs serialized as object keys. Preserve these identity rules rather than treating names as stable keys.
- Match `md`, domestic `data_cutoff`, history cutoffs, and history series entries can be null. Preserve null instead of substituting zero or an empty string.
- Notes files are optional per competition, like match and history data. A present file records its forecast origin in `as_of`, the exact result seasons loaded in sorted `seasons`, and the earliest one in `first_season`; missing years are not implied by the endpoints.
- Predictions can be absent. If `p` exists, require its full companion group: `exp, top, btts, o25, at`. `call` supports older optional data; `p_score` applies when an observed score is available. `xg, reported, stage, neutral, stakes` are conditional fields.
- Optional match `published` is a boolean. Finished fixtures with `published: true` use the receipt's forecast fields and its run `generated_at` as `at`; fixtures without a receipt retain reconstructed forecasts and omit the flag. For published fixtures, `p_score` is included only when the actual score occurs in the saved `top` or `call`; it never comes from a reconstructed forecast.
- A `FINISHED` fixture requires an integer home/away score pair. Forecast fields on finished fixtures describe the prior forecast, not a post-result prediction. Unknown provider status strings are not automatically malformed; retain existing status interpretation.
- Parse timestamps with an explicit timezone and dates as calendar dates. `generated_at`, forecast origin `as_of`, and result `data_cutoff` are distinct. Match-file `generated_at` currently represents forecast origin; table generation time represents execution time.
- Domestic result cutoff covers current-season completed results. UCL cutoff covers training results across leagues, and its exporter substitutes `as_of` when a result cutoff is unavailable.
- Do not require every forecast time to precede kickoff: an unplayed postponed/cancelled fixture can retain an old kickoff while receiving a new forecast. Pre-match timing protection belongs to completed-match forecast tests.
- Receipt `generated_at` is the competition run's execution timestamp, distinct from the match-file forecast origin. It must strictly precede the saved kickoff. Only fresh competition exports save receipts, for unplayed fixtures with a forecast whose kickoff is after both the run and the build time. Before kickoff a receipt can be replaced; after its saved kickoff it is immutable, even if a later feed reschedules the fixture. Retained competitions write nothing. There is no historical backfill.
- Domestic model `*_match_forecasts.json` and match snapshots carry optional `understat_id` from the existing score/kickoff-checked xG join. It is an internal provider identifier, omitted from published `matches/<competition>.json` and all probability calculations. Shot ingestion reads it from fresh model outputs and checks against the staged published fixture.

## Consistency checks

Reject nonfinite numbers, malformed required dates, wrong tuple lengths, duplicate scoped identities, invalid route references, nonpositive/noninteger simulation counts, negative fixture/played counts, and out-of-range probabilities or ratings. Scores are nonnegative integers. Points and goal difference can be signed because deductions and losing records are valid; do not impose nonnegative expected points or point quantiles universally.

Within each competition:

- Position-probability vector length equals team count; current positions form the appropriate table permutation. Each position-matrix row and column sums to 100% within export-rounding bounds.
- Domestic title chance matches the first position, and zone chances match their inclusive position slices. Expected position matches the weighted position probabilities within its separate rounding bound. Require `p10 <= p90`; the mean need not lie inside that interval.
- UCL `r16 + playoff + out` sums to 100%. Top-eight, playoff, and eliminated totals conserve 8/16/12 places; round-of-16, quarterfinal, semifinal, final, and title totals conserve 16/8/4/2/1 places. Progression is nested and top-eight probability does not exceed last-16 probability.
- Bracket tie participants are valid UCL teams, the winner is one of its participants, and the champion matches the final winner. Validate advancement range and tuple identities without pretending the illustrative bracket is the only possible draw.

Within matches, notes, and history:

- Match outcome triples sum to one; a present `top` is nonempty, finite, and sorted by probability. Pair/tuple lengths and units are fixed. Stakes counts are nonnegative integer triples; metric triples preserve nulls and known percentage ranges.
- Notes coverage seasons increase strictly, `first_season` equals the first listed season, and note fixture IDs exist in the matching competition fixture file. `generated_at` and `as_of` stay aligned with that competition export. Each fixture carries at most six dated head-to-head meetings and at most eight notes in either mode (four per side).
- Receipts obey the same forecast probability, scoreline and stakes checks. Published finished fixtures must have a forecast with `at` strictly before kickoff. Receipt filenames and season directories must agree with their `slug` and `season`.
- History dates strictly increase and each metric series has exactly `len(dates)` entries. Week dates strictly increase and represent Mondays; missing days and weeks are valid. Rating-run files are nonempty, their `month` matches the filename, and run `as_of` values are timezone-qualified, strictly increase and fall in that UTC month. The history season's start year matches its directory (`2026/27` → `history/2026/`), while older-season members may differ from today's clubs.
- Published club ranking numbers form the relevant rank sequences; overall list order agrees with overall rank. Featured IDs reference available ranked clubs. Crest paths, where declared, resolve to the published assets.
- Match-detail IDs and competition slugs agree with their paths; retrospective chances sum to one, player IDs are unique within each side, and Understat retrieval is after kickoff. Current-season files must match a finished published fixture with the same ID and kickoff. At ingestion, each side's shot xG sum must be at least its published match `xg` minus 0.05, and `Goal` shots plus opposition players' own goals must equal the final score. The sum may exceed the match figure, because Understat's match xG counts shots from the same attack as one chance (1 − ∏(1 − xG)). Later dataset validation repeats only the identity and status checks, so a provider revision or a corrected result after publication cannot block a refresh. Older season files remain valid without today's fixture list.
- Every per-match JSON file must be strictly under 60,000 UTF-8 bytes (60 KB), including all merged providers. Validation checks both the actual file size and compact serialized size before ingestion writes it. UEFA detail requires its source, Champions League, retrieval after kickoff and matching physical player identities; heat grids are exactly 294 nonnegative integers, selected players have at least 30 minutes, and their combined cells cannot exceed the team grid. Positions have unique player IDs and shirt numbers. Ingestion checks a unique date/home/away match in the season listing, finished status and final score equal to ours before publishing. Later validation retains the checked score without comparing subsequently corrected results.
- ESPN detail requires `sources.espn` with retrieval after kickoff. Possession sums to 100 within 0.2 percentage points, shots on target cannot exceed shots, event minutes agree with their displayed clocks, and timeline goals reconcile with the saved ESPN score. Ingestion requires a unique home/away name match on the same competition and UTC date, plus a completed ESPN event with a final score equal to the published fixture, checked in both scoreboard and summary. No ESPN fields are published on failure. Later validation does not recheck saved scores against subsequently corrected results, preserving fetch-once behavior.

Across files, each index entry agrees with its table's identity and generation metadata. Nonnull club league slugs and required file references resolve. Do not require universal membership or equal timestamps/seasons between independently retained tables, matches, ratings, and history. `scale.clubs` describes the model's reference population, not the length of the published clubs array; the ranking holds the five leagues' clubs and the current UCL field, and weekly history can hold clubs that have since left both.

## Rounding budgets

Use tolerances derived from serialization precision, separate from numerical regression tolerances. Never use a relative tolerance that grows with the magnitude of an invalid percentage.

For `m` values independently rounded to `d` decimal places, their sum has an error budget of `m × 0.5 × 10^-d`, plus a small explicit floating-point allowance. When comparing two rounded quantities, include the rounding contribution from both sides.

- Match `p` values have four decimals: use `0.0002` absolute tolerance for the triple's sum to one.
- Table probability cells have two decimals: a row or column with `N` values has a sum budget of `N × 0.005` percentage points, plus any documented precision lost in intermediate model files.
- Comparing a rounded zone value to `m` rounded position cells needs `(m + 1) × 0.005` percentage points, plus any intermediate-file rounding.
- Expected position weights cell errors by position: its bound is `0.005 × sum(1..N) / 100 + 0.005` places, plus documented intermediate rounding. The final term allows the displayed expected position's own rounding.
- Historical chances and stakes use one decimal below 10% and whole percentages at/above 10%. Do not enforce aggregate probability sums or exact agreement with today's two-decimal table on those series.

Document any extra allowance for upstream CSV precision. Keep range checks strict for directly rounded probabilities; allow rounding bounds when checking derived sums or relationships rather than making every numeric field broadly permissive.

## Validation and publication

Run exporter tests on frozen model outputs and validate their generated JSON. Include deliberately invalid examples: missing required fields, a 0–100 match probability triple, wrong tuple lengths, NaN, duplicate IDs, a broken index reference, and a history series of the wrong length. Include valid examples with null IDs, absent optional forecasts/history/crests, point deductions, and retained older competition files.

Exporter tests must also compare known input/output meanings, including tuple order and units. Swapping valid home/away probabilities can preserve types, ranges, and the sum; a schema cannot infer that semantic mistake from the JSON alone. Known fixture expectations provide that protection.

During refresh, assemble fresh exports and retained files into a candidate dataset, then validate the entire candidate before committing or deploying it. At least one successful forecast remains necessary for a successful refresh; all-six failure keeps the existing failure behavior. Invalid candidates fail publication and leave the deployed site in place. Do not mark retained data as freshly generated or add history points from a failed forecast.

Every refresh with a fresh Champions League fit appends its club ratings to `history/<season>/ratings/<YYYY-MM>.json`, dated by the fit's forecast origin `as_of` with its result `cutoff`. A run at or before the month's latest `as_of` is not added, so reruns of the same outputs add nothing and earlier runs are never rewritten; a retained Champions League forecast adds no run. The finished match page's Strength block compares the last run with `as_of` before kickoff and the first run whose `cutoff` reaches kickoff, loading the kickoff month and, only when needed, the month either side. The runs from 13 October 2026, 12:51 UTC, to 15 October 2026, 00:38 UTC, were reconstructed from the `clubs.json` and `champions-league.json` committed at each refresh; earlier refresh commits lack an `as_of` or carried ratings from a different run, so they were left out and games before then show a note instead of a change.

`notes/<competition>.json` is rebuilt only when that competition's forecast and match files are fresh; a retained competition keeps its prior notes and timestamps. The exporter reads saved domestic CSV and Champions League API cache entries directly, plus the current match snapshot. It never fetches history: unavailable cache years are skipped and listed in `seasons`, so gaps remain visible and are not treated as continuous coverage. For completed historical CSV rows with a known kickoff, availability is conservatively treated as kickoff plus three hours; date-only rows count from the next local midnight. Current API results use kickoff plus three hours. Pre notes require `available_at < fixture kickoff`. Post notes use those earlier results and the fixture's own completed result; other results from that kickoff or later are excluded. The frame lists the exact covered seasons and hides when both its note list and meeting list are empty. If a fresh optional note export fails, its old note file is removed so stale timestamps cannot invalidate the new competition data.

Site-only publication validates the data shipped with that revision. Deploy the exact immutable artifact that passed validation: a later checkout of moving `main` is a different candidate and needs validation again. Daily bot commits do not trigger other workflows, so refresh must invoke the same gate explicitly. No provider access is needed for PR checks or data validation.

Old but valid data is not structurally invalid. Treat freshness separately from schema validity; the current global updated indicator uses the newest competition and can conceal an older retained competition.

`scripts/fetch_match_events.py` runs after exports and before candidate validation in `refresh_site.sh`. It fills finished domestic fixtures with joined Understat IDs on the next refresh, including the existing season's games. Successful derived Understat data is never refetched or replaced; files from another source keep their keys when Understat is added. Raw payloads and failed-attempt markers live in uncommitted `.cache/understat/matches/`. Requests are at least one second apart, with one attempt per fixture per run. A first attempt is allowed for older games; subsequent failed attempts retry only through seven days after kickoff. Fetch, missing-data and consistency failures log warnings and publish no Understat data; they never fail a forecast refresh. Retained competitions without fresh model outputs are skipped.

The same entry point also calls `scripts/fetch_espn_events.py` for all six competitions (or select `--provider espn` / `--provider understat`). ESPN uses one cached scoreboard per competition/date and one summary per mapped event, under `.cache/espn/matches/`, with the same one-request-per-second, seven-day retry and warning rules. Normalisation reuses the existing team-name function plus `scripts/espn_team_overrides.json`; ambiguous and absent mappings are warnings naming the fixture. The run reports score-checked mapping coverage for the previous Monday–Sunday UTC week, including already published ESPN sources. Published ESPN fields are never refetched; other source fields and forecast timestamps are preserved. Retained competitions are skipped. The frontend uses ESPN goals and red cards on the existing xG lines when present, keeping Understat goal markers as the fallback; games without shots get a minute ruler. Full substitutions appear only in the collapsed Full timeline.

UEFA runs from the same entry point (`--provider uefa`, or the default `all`) via `scripts/fetch_uefa_events.py`, after ESPN. Raw season listings, team statistics, player statistics and lineups are cached under `.cache/uefa/`, with failed fixture markers by season. The listing uses the season end year plus `offset=0&limit=500`, refreshed once per run only when unpublished fixtures need it; successful per-match payloads are reused. Mapping uses UTC date and normalised names, including UEFA's English official/display names and the existing ESPN overrides; no new overrides were needed for the current fixtures. It checks lineup match/team IDs as well. Requests are one second apart, first attempts may backfill older games, and failures retry through kickoff plus seven days. A failure warns with fixture ID/date/teams, publishes no UEFA fields and never fails refresh. Existing Understat/ESPN fields and sources survive the merge. Retained Champions League forecasts are skipped. Run output reports every unmapped/unpublished fixture, season mapping coverage and the largest merged Champions League file. Published UEFA data is never refetched.

The 14 October 2026 scratch backfill covered all 27 finished 2026/27 published fixtures (matchday 1 and the first half of matchday 2): 82 requests in about 84 seconds. Two reruns made zero requests. The largest merged file was Viking v Bayern, fixture 575347, at 38,674 bytes. Allow about two extra minutes for the first CI refresh at this coverage, on top of the earlier ESPN backfill's roughly twelve minutes; later refreshes ingest only newly finished matches. Generated match data is left to the next refresh.

## Compatibility and changes

Allow additive fields so compatible exporter additions do not force a site update. Removing a consumed field, changing its meaning/unit, changing tuple order, tightening nullability, or changing a required shape is a breaking change even if the JSON still parses.

A breaking change must update schemas, exporter, affected consumers, fixtures, and documentation in the same review. Migrate retained data and older histories or provide a deliberate compatibility path; relying on the next successful model refresh leaves old files exposed. Start with one current contract rather than maintaining several parallel versions.

Passing this gate means data is valid under this contract. The browser checks then show that every view renders from it without script errors; neither proves the numbers are right.


## Scorecard

Each competition and `all` contains a combined record plus `published` and `reconstructed` records with the same shape. These are disjoint fixture cohorts: the combined record uses a receipt when present, otherwise the full-precision model row from `*_match_forecasts.json`. It counts every finished fixture with a forecast once, including published fixtures whose replay has no forecast. A published forecast requires the finished exported fixture's `published: true`, populated from `history/<season>/forecasts/`. Other statuses and fixtures without a forecast are excluded. All scores cover the 90-minute home/draw/away outcome, in that order.

Each record contains `n, n_published, model, baselines, called, exact, avg_chance_given, calibration, weekly, market`. `model` and each of the `frequency` and `elo` baselines have `n, log_loss, brier, rps`. Each baseline also has a `model` score on exactly its covered fixtures, so comparisons remain paired even when coverage differs. `called` and `exact` are counts; `avg_chance_given` is the average probability of the actual outcome. `market` is null until Task 14. Empty samples have null scores and chance given, zero counts and no weekly points.

- Log loss is mean `−ln(P(actual outcome))`, with zero probabilities floored at `1e-15` for finite exports. A uniform one-in-three guess has log loss **1.098612**, displayed as 1.099.
- Brier is the mean sum of the three squared probability errors (range 0–2).
- RPS is the mean of the two squared cumulative probability errors, averaged over the home and home-or-draw thresholds (range 0–1).
- The ten half-open probability bins are `[0,.1), …, [.9,1]`, pooled across all three outcomes. Each holds `lo, hi, n, probability, observed`; empty-bin means are null. Bin counts sum to `3·n`.
- `weekly` holds cumulative mean scores for `model, frequency, elo`, each with its covered `n`, through the end of the UTC week beginning on `week` (Monday). It includes all earlier scored fixtures, not just that week's matches. `all` weights scores by fixture count and carries each competition's latest cumulative observation forward.

`frequency_baseline` on a competition records `requested_seasons` (the five season start years before this season), actually loaded `seasons`, historical `n`, and a single fixed `p` vector. Forecast runs reuse the result history they load and fetch only the missing prior seasons, without adding these extra seasons to strength fitting. Results must precede 1 July of the forecast season (and their availability timestamp must too, when supplied). The exporter stays offline. `p` is null until all five seasons are available; coverage remains visible. Historical results come from the existing domestic CSV/API adapters and Champions League API. The baseline covers all finished fixtures in those competition seasons, including Champions League knockouts, using 90-minute scores.

The model adds `elo: [home, draw, away]` to fixture forecasts, preserving blended probabilities. Site fixtures and future receipts copy this component at six decimal places. Existing frozen receipts without it stay unchanged and have no Elo comparison; a reconstructed Elo component must never substitute for a missing published one. Failed competition refreshes keep the prior scorecard entry and its original timestamp. Before a first successful scorecard export, a retained competition can be absent from `competitions`.

Published and reconstructed counts accompany every cohort. Retrospective seasons used to calibrate settings are not independent holdouts, and Champions League strengths already incorporate archived market prices. Proper scores describe this sample; they do not establish prospective calibration or market independence.

## Squad references

`squads/<season>/<slug>.json` is optional and loads independently of forecasts. The directory and `season` are the four-digit season start year. Each file identifies `slug, club_id, name`, a content-derived `baseline_id`, and `generated_at` (the first creation time of that exact baseline). Current-season identities must agree with `clubs.json`; older seasons need not match today's membership. No squad data changes forecast probabilities.

- `ratings` contains `source: "EA SPORTS FC"`, edition, normalized `snapshot_date`, pinned CSV URL, filename, SHA-256 and men's row count. Its vintage is a publisher claim. One edition/snapshot is allowed per file. `identity_overrides_sha256` pins the reviewed exceptions; `method` is `ea-position-assignment-v1`.
- `roster` contains `source: "football-data.org"`, `status`, actual UTC `observed_at`, API URL, raw archive `sha256` and repository-relative `snapshot` path. `available` requires a nonempty player list. `unavailable` means the provider returned an empty squad: publish an empty list, zero coverage, eleven unfilled slots and `insufficient_coverage` on first export. If any file already exists for that club, retain it instead, including its timestamps. A missing supported club in the competition response or a malformed squad fails the build.
- `coverage.players` is the player-list length; `coverage.matched` counts `status: "matched"` and cannot exceed it. Every observed player remains visible with football-data.org `id, name, dob, provider_position, status, method`. Birth date and provider position may be null. Original provider birth dates are preserved even when an override verifies a correction. Overrides carry their evidence URL and observation date. Unmatched/ambiguous players have null `ea` and a `reason`; suggestions are confined to local pilot reports.
- Matched `ea` contains its separate provider `id`, integer `overall` on 1–99 or null, listed `positions`, and `pace, shooting, passing, dribbling, defending, physical` on 0–99 or null. `physical` maps the CSV's `physicality`. For a player whose first listed position is GK, EA stores the keeper card stats in the same six fields, in order: diving, handling, kicking, reflexes, speed, positioning; the site labels them that way. Missing stats stay null; published zeroes are source values. These are EA face stats, not model estimates. Never join numeric IDs across providers.
- `ideal_xi` contains `formation, status, mean_overall, slots`. Each of eleven ordered `{role, player}` slots references a squad ID or null. Assigned players must be uniquely selected, matched, rated and eligible for the role (LW/LM and RW/RM are compatible). Unfilled slots require `insufficient_coverage` and a null mean; a filled XI is `provisional` unless the entire squad has usable ratings/positions. A full XI's mean is its eleven EA overalls averaged and rounded to one decimal. Everyone is assumed available; this is neither a predicted lineup nor a probability/goal adjustment.

The latest eligible dated observation wins when domestic and European snapshots for a club differ. Contradictory squads at the same observation time fail. Duplicate IDs within a club fail. Provider IDs assigned to multiple clubs are explicitly quarantined as ambiguous in every affected squad (`provider_id_in_multiple_clubs`); no current membership is guessed from different observation dates. Duplicate EA identities remain quarantined by the matching code. The local pilot keeps its strict rejection of repeated provider IDs and empty squads.

Each raw roster observation is archived immutably at `data/players/rosters/<UTC observation date>/<code>.json`. Online refresh reuses the most recent observation for seven days across both the supplied cache and committed archive; offline runs select the latest observation before the end of `--roster-date` without network access. Historical replay does not pretend that an old cache is current. Requests for new competition squads are spaced seven seconds apart. An archive collision with different bytes fails instead of rewriting an observation.

Frozen per-club references live at `data/players/baselines/<season>/<slug>/<baseline_id>.json`. Identical inputs reproduce the content ID and reuse the first creation timestamp and file bytes. Changed inputs create a new baseline, leaving previous ones intact. Earlier matches cannot use today's baseline as pre-match evidence. Season participation is a separate, retrospective layer, added by `scripts/build_squad_usage.py` after the baseline export. It never changes the frozen baseline ID, baseline `generated_at` or archived reference. `usage_generated_at` dates the current usage content; identical inputs retain this timestamp. Older files without usage remain valid.

- `usage` has one entry per published competition the club plays in the same season (including zero finished games). Domestic entries have `source: "understat"`; Champions League entries have `source: "uefa"`. `games` counts finished published fixtures and `covered` counts structurally complete source sheets, including sheets with unmapped names; `fully_mapped` counts those with every appearance mapped to the squad. `games_list` is ordered by kickoff and fixture ID. These are observations against today's squad, not pre-match features or historical registration claims.
- Each usage `players` key is a football-data.org squad ID. `starts, sub, minutes` sum **known observations**, including mapped appearances on partial sheets. `known_games` counts complete sheets plus partial sheets on which that player appears; `unknown_games = games - known_games`. With no known games, all three totals are null. An unobserved player gets zero only for a fully mapped side; absence on a partial or missing sheet remains unknown. Totals with unknown games are lower bounds, not claims of season-long absence. Understat cohorts add season `xg` and `xa` totals over the same known observations (null with no known games), and their appearance rows carry each game's `xg, xa`; UEFA cohorts have neither. `provider_ids` retains the distinct Understat or UEFA IDs behind that player's observations, scoped to this entry's source. Name matching uses the pinned EA full/common names and verified aliases through `identify_appearance`; provider numbers are never joined across sources. Duplicate squad assignments or conflicting source-ID bindings are unresolved.
- `share = minutes / (90 × covered)`, rounded to six decimals, or null when the denominator is zero or participation is wholly unknown. It is an observed-minutes ratio, not a bounded probability: UEFA includes stoppage time, and known minutes on partial sheets also enter the numerator. It can exceed one through stoppage time; read it with both competition and player coverage. Understat minutes exclude stoppage time. Never pool the competitions or cap their minutes.
- `most_used_xi` contains `formation, status, slots` with the same role eligibility and unique squad references as the ideal XI. `select_xi` maximizes filled roles, then summed observed minutes at source precision (tenths), then summed EA overall, then its existing position/stable-ID preferences. Only rated players with positive known minutes are eligible; otherwise roles stay unfilled. Coverage status follows the eligible pool, so a filled XI is provisional when other squad members lack eligible evidence.
- Each `games_list` row identifies `fixture_id, kickoff, opponent_id`, `status` (`complete`, `partial`, `missing`), `reason`, and `sheet_sha256` (the published match file hash, null if there is no file). Missing provider keys mean `missing_match_sheet`; invalid starter counts, duplicate provider IDs or infeasible minutes mean `invalid_match_sheet`/partial with no known appearances. A valid sheet with unresolved names is `unmapped_appearances`/partial. `appearances` retains every valid source row's `source_id, name, minutes, starter` and mapped squad `player` (null if unresolved), so mapped plus unresolved totals reconcile with the sheet. `starters` and `subs` contain mapped squad IDs only. Understat's `position == "Sub"` identifies a substitute; UEFA's eleven `positions` rows identify starters and positive `physical.players` minutes identify all appearances. Minutes thresholds and heatmap eligibility never decide starts. `ideal_started` counts ideal players starting when the ideal XI has eleven players and either all eleven starters are mapped or all eleven ideal players have known participation; otherwise it is null.
- UEFA usage players also have `avg_x, avg_y`, null without starter-position observations. These are unweighted means of UEFA starter average locations, rounded to four decimals. Before averaging, away coordinates are rotated (`1-x, 1-y`) to the home orientation: own goal at x=0, attack toward x=1, player's left at y=0. Substitutes retain minutes even without a published position; heatmap grids are not used. Appearance rows keep these normalized coordinates for reconciliation.
- Average positions are shown as observed, without a derived role label: they shift with possession and opponent, so fixed pitch zones misclassify players (goalkeepers read as centre-backs).

The schema checks these shapes; the validator reconciles counts, starts, minutes, shares, unknown states, positions and provider identities from the ledger, checks XI eligibility, and verifies fixture identity. If a saved sheet hash still matches the published file, it also reconciles every appearance and coordinate directly with that source. A retained usage snapshot can omit newer fixtures or reference an earlier sheet hash; optional refresh failure must not relabel its data as current.

The Squad view (plan Task 5) reads `usage` when present and otherwise renders exactly as without it. It reads, per competition slug from the site's competition list, `games`, `covered`, `players` (keyed by squad player ID: `starts`, `sub`, `minutes`, `share`, and season totals `xg` and `xa` for league cohorts), `most_used_xi` (`formation` and eleven `{role, player}` slots like `ideal_xi`) and `games_list` (`fixture_id`, `kickoff`, `opponent_id`, `status` of `complete | partial | missing`, `starters`, `subs`, `ideal_started`). A player absent from `players` is shown as unknown, never as zero. Cohorts are displayed one at a time and never summed.

After forecasts and match ingestion, `refresh_site.sh` builds squad baselines and then season usage in a separate candidate, validates it, and copies squads into the forecast candidate only on success. It downloads the commit-pinned CSV with `--download-players` and checks `data/players/ea.sha256` before parsing or fetching rosters; failed downloads/checks/builds retain all previous squad files and timestamps and do not fail forecasts. The complete combined dataset is still validated before publication. Archives and baselines are committed by the refresh workflow. PR checks remain offline.
