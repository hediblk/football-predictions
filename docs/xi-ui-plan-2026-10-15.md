# Squad XI, usage history and forecasting tasks

Agreed direction, 15 October 2026. Start with La Liga and a **Squad** subtab on each club page. The [local pilot](squad-matching.md) supplies frozen rating-based ideal XIs and domestic usage comparisons. This plan adds publication, UI and a later forecasting experiment; none is implemented by this document.

## Evidence and source choice

The current squad snapshot matches 470/520 players to EA; all 20 clubs can fill a position-constrained XI, but 18 clubs' references remain provisional because some squad members are unrated. Current UEFA files cover 36 Champions League fixtures, including ten club-games for five La Liga clubs. The identity audit matches 159/159 participating-player records, 129/129 heatmap-player records and 110/110 starters. One verified Abde/Abdessamad alias was needed.

Use the data accompanying heatmaps to identify starters, rather than inferring them from the grids. `positions` comes from UEFA's lineup `field`, including starters who leave before 30 minutes; `physical.players` supplies all positive playing times. Player heatmaps require at least 30 minutes and also include substitutes: the audited sample contains 19 such substitute appearances. Average locations are observed positions, not formation coordinates. Domestic match sheets instead use Understat's `position != Sub` starter flag. There are currently no domestic activity heatmaps.

The heatmap source therefore supports the proposed XI history. Grids themselves are optional spatial context; they are not the denominator for starts or playing time. UEFA minutes include stoppage time, whereas Understat's minutes use a different convention. Keep their competition/provider cohorts separate.

## Task 1 — Publish squad references and match participation

**Depends on:** the local matching pilot. **Deliverable:** checked, optional club squad JSON, with no UI or forecasting change.

- Extend the existing exporter/refresh boundary, using a per-club file loaded on demand. Specify fields in the [site data contract](site-data-contract.md) and schema before adding a consumer. Resolve source redistribution terms before publishing EA ratings or derived data.
- Retain dated ideal-XI snapshots outside ignored `out/`, with source hashes, squad observation time, edition/rating vintage, formation, identity coverage and creation time. An identical rerun preserves the original time. A failed refresh retains the previous file and timestamps.
- Produce a season participation ledger for **all observed players**, not only the ideal XI. Store fixture, club, provider player ID, mapped squad ID, starter/substitute state, minutes, source and observation time. Do not join numeric player IDs across providers. Preserve departed players and match-time club membership rather than dropping them against today's roster.
- For La Liga use existing Understat sheets. For UEFA use lineup-derived `positions` and `physical`; require eleven unique starters for a complete XI. Missing sources, ambiguous identities and conflicting assignments stay unknown. An absent player gets zero minutes only when the complete participating roster is accounted for; unused bench and reasons for absence remain unavailable.
- Link each prospective comparison to the baseline available before kickoff. Earlier actual lineup history is useful, but comparisons against today's ideal XI must remain explicitly retrospective. Do not invent historical ideal XIs.

**Done when:** all 20 pilot clubs have an honest coverage/freshness state; the heatmap identity check is reproducible; early substitutions and long substitute appearances produce correct starter flags; retained/missing data is represented without fabricated zeros. Run relevant existing model and publication checks. Do not bulk refresh forecasts for this work.

## Task 2 — Add the club Squad subtab and ideal XI

**Depends on:** Task 1. **Deliverable:** a small club-page addition in the existing static site.

- Keep the club overview as the default. Add **Overview / Squad** within the club page, with proposed direct route `#clubs/<slug>/squad`; preserve existing club and comparison links. No new top-level navigation.
- Show the reference XI on a pitch with assigned roles and an accessible player list. Explain the chosen formation and everyone-available assumption. Display EA edition/vintage, baseline date and matched/squad coverage; label provisional references and unfilled roles.
- Provide a compact squad table with names, listed roles and available ratings. Distinguish **EA overall** from Floodlight's existing club strength rating. Do not describe an EA rating gap as goals lost or a change in win probability.
- Reuse [DESIGN.md](../DESIGN.md), existing typography, tokens and compact layout. Load squad data only when needed. Provide missing-data states, keyboard navigation, browser back/forward behavior and a readable narrow-screen layout.

**Done when:** the pilot works for Barcelona, a club with unmatched players and an unavailable file, at desktop and 375px widths; every pitch player is available in the list; direct links and existing comparisons work. Run data validation and the existing browser checks against the exact candidate site.

## Task 3 — Add actual XI history, minutes and squad usage

**Depends on:** Tasks 1–2. **Deliverable:** history and player usage within the same Squad subtab.

- Show each game's **actual starting XI**, substitute appearances and minutes, linking to the existing match page. Show a heatmap link only where that source exists. Keep actual XI history distinct from changes to the frozen ideal reference.
- Offer a competition/season cohort and show the covered-game count. Start with league and Champions League views separately; do not silently pool their minute conventions.
- Per player: starts, substitute appearances, total reported minutes and average minutes per appearance. If offering average minutes per club game, divide by fixtures with known participation, including confirmed zeros and excluding unknowns; show that denominator. Do not divide by the number of heatmaps.
- Per match: ideal players starting (`n/11`) and ideal minutes share (`100 × sum(min(minutes, 90)) / 990`). Suppress full-XI metrics when roles or participation are unknown. Show rotation against the previous completely covered starting XI and disclose skipped games.
- An optional descriptive squad rating can compare mean EA overall of actual starters with the frozen ideal XI, using the same rating vintage. Require all eleven actual starters to be rated for a rating gap; otherwise show `rated n/11`. Label it as an EA rating comparison, with no forecast adjustment or causal absence claim.

**Done when:** totals reconcile to the participation ledger; missing sheets and identities do not become absences; denominators, rating vintage and retrospective comparisons are visible. Review a starter leaving early, a long substitute appearance, a player with no appearance and a partially mapped game. Run existing publication/browser checks.

## Task 4 — Evaluate a lineup-based boosting model

**Depends on:** a broad, dated lineup/outcome dataset from Task 1 and additional historical collection. **Deliverable:** an offline experiment and report first. It has zero production weight until a separate, justified integration change.

**Hypothesis:** starting-player quality and rotation add information beyond the current team-level model. Compare LightGBM or XGBoost with a simple regularized baseline before choosing an implementation. Begin with one pooled model across teams, using team/opponent context; a separate model per team is a later comparison if learning curves and held-out coverage support it. With only a few games per club, independent fits would have too little evidence to estimate lineup effects reliably.

Use both teams' starting XIs, venue, role-level rating summaries, missing-reference players, and prior-only team/opponent strength/form. Begin with compact aggregates rather than hundreds of individual-player interactions. Outcomes, goals and observed match xG are **targets**. Minutes, substitutions, heatmaps, match xG and results from the game being predicted are unavailable as pre-match features. Observational lineup effects also reflect coach selection, opponent strength and match context; they are not causal player valuations.

Two related target experiments are reasonable:

1. Calibrated home-win/draw/away-win probabilities, reported as team win/draw/loss if eventually exposed in the UI.
2. Nonnegative home/away match-xG estimates (equivalently each club's xG for/against), using a consistent xG provider and distinguishing these from expected actual goals. Compare any goal-rate integration separately rather than silently feeding predicted xG into the score model.

Collect several seasons/leagues where possible and report fixtures, lineup completeness, teams, seasons, rating coverage and exclusions. There is no assumed magic match-count threshold: use learning curves, lineup variation and uncertainty to decide whether an experiment is representative. The current ten Spanish UEFA club-games are an identity check, not a training set.

Every feature needs availability before the forecast origin: historical squad membership, player identity, EA edition/snapshot, opponent ratings and lineup announcement. Today's EA snapshot or roster cannot support a leakage-free multi-season replay. Historical lineups without publication receipts can support a labelled retrospective/oracle analysis, not proof of live forecast improvement. Archive future confirmed lineups and observation times. A confirmed-XI model applies near kickoff; daily forecasts require a separately evaluated expected-lineup method or retain the existing model.

Evaluate by expanding chronological date/season windows with a final untouched period. Keep a fixture's two team perspectives in the same split; fit preprocessing, feature selection, early stopping, hyperparameters and probability calibration on earlier data only. Disclose prior seasons that already influenced choices. Compare baseline and augmented forecasts on identical covered fixtures and horizons, with fixed seeds and separate no-odds/odds reporting. Use log loss, Brier score and calibration for 1X2; MAE/RMSE and bias for xG for/against. Check season/club stability, learning curves and uncertainty, and compare a simple XI-rating adjustment to establish the benefit of boosting.

Only a reproducible incremental gain justifies a small ensemble weight, selected using earlier validation folds and then checked unchanged on holdout. Include zero in that comparison; a low weight does not fix overfitting. Keep this signal separate from existing team strength to assess double counting. Save training cutoff, feature/source hashes, settings and candidate weight. Production integration must be an explicit calibration task, preserve `--as-of`, use a saved artifact and fall back to the existing forecast when a dated XI is unavailable; it must not silently replace `calibrated_weights.json`.

**Done when:** a reproducible report states whether lineup features improve the existing model on genuinely later data, with coverage and timing limitations. A negative result is a completed experiment. No new dependency, training run, forecast weight or published probability is part of the current pilot merge.

Implementation references: [LightGBM objectives](https://lightgbm.readthedocs.io/en/stable/Parameters.html#objective) support classification and regression; [scikit-learn's time-series split guidance](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html) explains why training on later observations invalidates earlier evaluation. Football folds should use explicit date/season boundaries because fixtures are not equally spaced.

## Suggested delivery order

Task 1 → Task 2 → Task 3. Start the dated-data inventory and collection portion of Task 4 alongside Task 1; train/evaluate only once coverage and rating vintages permit it. UI value does not depend on the boosting experiment succeeding.
