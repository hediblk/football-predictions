# Squads and players plan, 15 October 2026

This plan follows the [ideal-XI pilot](squad-matching.md). It splits the player work into tasks that one agent session (Codex or Claude) can finish and open as one pull request each:

- **Squad data and UI first:** EA ratings, an ideal XI and actual playing time for every supported club, in a new **Squad** subtab of each club page.
- **Model data next:** past lineups and rating vintages, so a player model can be fitted.
- **Player-adjusted forecasts last,** only if they beat the current model on later seasons.

Only Task 14 (scorecard market comparison) remains from the [previous feature plan](feature-plan-2026-10-14.md).

## Decisions

- **EA SPORTS FC is the only rating source.** One edition and snapshot per baseline, as the pilot enforces. Ratings are shown on the site, and the footer credits EA SPORTS FC as the player-rating source.
- **All competitions from the start.** Task 1 covers the five leagues and every Champions League club in `clubs.json` (111 clubs). The La Liga pilot proved the matching; other leagues mostly add identity exceptions, which coverage figures show honestly. A Squad tab that works on 20 of 111 club pages is not worth shipping.
- **Playing time comes from match sheets, not heatmaps.** Understat rosters supply minutes, starts and substitute appearances for domestic games; UEFA `positions` and `physical` supply them for Champions League games. Heatmaps exist only for players with 30+ minutes in Champions League games, so they show **observed position**: where a player actually played, compared with EA's listed position.
- **One pooled player model, not one model per team.** A club plays about 38 league games a season. If a regular starter misses about 25 of them over four seasons, a with-or-without comparison of team xG has a standard error near 0.9 / √25 ≈ 0.18 per game. That is about the size of a star's effect, before accounting for which opponents those games were against. A pooled model shares one scale across about 44,000 team-games since 2014/15, carries a player's evidence across clubs, and falls back to the EA rating where minutes are few. The first model is a regularized xG plus-minus with EA ratings as the prior. LightGBM/XGBoost comes later, as a model of its remaining errors.
- **Forecasts use the expected or latest XI for now.** The confirmed XI (about an hour before kickoff) and injury data are nice-to-haves (N1, N2).

## Rules for every task

**Before starting:** read `AGENTS.md`, `DESIGN.md`, the [site data contract](site-data-contract.md), [ADR 0001](adr/0001-site-model-boundary.md), [ADR 0002](adr/0002-site-browser-checks.md), [squad-matching.md](squad-matching.md) and this task's section. Each task is one branch and one PR. Do not edit `deferred-notes/`.

**Data:**

- **Identity.** Match squads to EA by birth date and name, as `src/standing_prediction/squads.py` does. Source-backed exceptions go in `data/players/identity_overrides.json`. Never join numeric IDs across providers. Unmatched and ambiguous players stay visible as such.
- **Unknown is not zero.** A missing match sheet or an unmapped name makes participation unknown. A player gets zero minutes only when the whole side's sheet maps.
- **Keep competitions apart.** UEFA minutes include stoppage time and Understat's don't. Totals and shares are per competition.
- **No leakage.** Today's squads and ratings never become features of past forecasts. A rating vintage is usable from its release date.
- **Failed refreshes stay honest.** A failed squad refresh keeps its previous files and timestamps, and never fails the forecast refresh.
- **Ingestion volume:** at most one request per second to unofficial sources. Cache raw payloads under `.cache/`; commit only the derived or archived files the task names.

**UI:** follow `DESIGN.md` and the [previous plan's](feature-plan-2026-10-14.md) UI rules. No new top-level tab. Reuse the match page's pitch drawing (`pitchLines` in `match.js`), chips, ruled `board` tables and hairline meters. No new hues. Hide what has no data, state coverage where it is partial, give every graphic a text equivalent and check every change at 375 px. Label **EA overall** distinctly from Floodlight's club ratings, and never present a rating gap as goals or probability.

**Before opening the PR:** run the checks the change calls for: pytest with the `AGENTS.md` flags for Python changes; `scripts/validate_site_data.py --data site/data` for data; `scripts/check_site.py --site site` for UI, adding new routes to `routes()`. Update `DESIGN.md` and the data contract where the task changes them, and set the task's status below to its PR link. No docstrings or new tests unless asked; `PYTHONDONTWRITEBYTECODE=1`; delete any `__pycache__`.

**Parallel sessions:** worktrees have no `.cache/`. Read the cached EA CSV and roster snapshots from the main checkout's `.cache/players/`, passing paths as arguments. UI work goes in a new `site/assets/squad.js` and one appended, commented `style.css` block; data work goes in new scripts. Rebase before merging; `style.css`, `check_site.py` and the overview table usually resolve by keeping both sides.

## Wave A

### Task 1. Squad and ratings export, all competitions

**Goal:** a checked squad file for each of the 111 clubs in `clubs.json`, rebuilt by the refresh.

- Generalize `scripts/build_squads.py` to all codes (`PL PD BL1 SA FL1 CL`), keeping its checks. A club in both a domestic and the European response is matched once.
- **EA input in CI:** download the pinned EA CSV URL already in `build_squads.py` into `.cache/` and verify it against a sha256 committed in the repository. A mismatch or failed download keeps the previous squad files.
- **Rosters:** football-data.org squads change slowly. Fetch them at most once every 7 days (6 requests, within the refresh's existing rate-limit sleeps) and archive each dated snapshot under `data/players/rosters/<date>/<code>.json`. Treat these as immutable observations, like the odds archive.
- Write the squad files in the contract above, from a script called by `scripts/refresh_site.sh` after the forecasts. Make it a non-blocking step, like match-event ingestion.
- Raise identity coverage beyond La Liga. Review unmatched players using the pilot's `candidates`, regular starters first, and add source-backed overrides.
- Add the family to `schemas/site/data.schema.json`, the validator and `docs/site-data-contract.md`. The validator checks that slot players exist in `players`, that each player fills at most one slot and that `matched ≤ players`.

**Done when:** every supported club has a file or a stated reason it doesn't. A rerun with identical inputs leaves files and timestamps unchanged, a failed download keeps the previous files, and the existing checks pass. Report coverage per league in the PR.

### Task 2. Club Squad subtab: ideal XI and squad table

**Goal:** a Squad view on every club page, built against the contract.

- Under the club header, a two-chip **Overview / Squad** control. Overview stays the default. `#clubs/<slug>/squad` opens Squad, `#clubs/<slug>/vs/<other>` keeps working, and back/forward and direct links work. This needs a small router change in `main.js`.
- **Ideal XI frame:** a pitch (reuse `pitchLines`) with eleven dots placed by formation role, each labelled with surname and EA overall. Caption: formation, "Best EA-rated XI from listed positions, everyone available", mean overall, EA edition and snapshot date, matched/squad coverage. Mark provisional XIs and unfilled roles. A list below the pitch repeats every player as its text equivalent.
- **Squad table:** a ruled `board` table grouped by line (GK, DEF, MID, ATT), sorted by overall within each: name, age, EA positions, EA overall and the six face stats where available. Unmatched players are listed as "not rated".
- **Footer:** add "EA SPORTS FC · player ratings" to the Data links, pointing to `https://www.ea.com/games/ea-sports-fc/ratings`.
- New code goes in `site/assets/squad.js`; `clubs.js` gets only the control and a call into it.

**Development data:** until Task 1 merges, convert the pilot's `out/squads/PD.json` (main checkout) into contract files in a scratch copy of `site/`. Never commit them. Without files the view shows its missing-data note, and `check_site.py` must pass either way.

**Done when:** Barcelona, a club with unmatched players and a club without a file render correctly at desktop and 375 px. Keyboard use and screen-reader text work, and `check_site.py` covers `#clubs/<slug>/squad`.

### Task 3. Past lineups: Understat rosters since 2014/15

**Goal:** a resumable archive of every past league game's player rows, the training data for Tasks 6–8.

- Take match IDs from the Understat league files the model already caches (`getLeagueData`, 2014/15 onward). Fetch `getMatchData/<id>` for each finished game from 2014/15 to 2025/26: about 22,000 games at one request per second, roughly six hours. Run it in the background so it can resume.
- Cache raw responses under `.cache/understat/matches/`. Derive one compressed CSV per league-season, `data/players/understat/<league>/<season>.csv.gz`, with match ID, date, side, team, Understat player ID, name, position, minutes, starter or substitute, `roster_in`/`roster_out` links, goals, shots, xG, xA, key passes and cards. Add one team-game file with match xG for and against.
- Validate each match: eleven starters per side, unique player IDs, minutes 0–130, and summed player xG within tolerance of the team's match xG. Record exclusions with reasons.
- Commit the derived files with a short README covering source, fetch dates, coverage and exclusions, like `data/odds/README.md`.

**Done when:** the README has a coverage table (games, complete sheets and exclusions per league-season), and a rerun fetches nothing new.

## Wave B

### Task 4. Season participation and observed positions

**Goal:** the `usage` section of each squad file, for every competition the club plays this season.

- Build a participation ledger from the published match files: Understat rosters for domestic games, UEFA `positions` and `physical` for Champions League games. Map names with `identify_appearance` as the pilot does, keeping provider IDs per player.
- Per competition: games and games with a complete sheet. Per player: starts, substitute appearances, minutes and share of available minutes (minutes ÷ (90 × covered games)). For the Champions League, add mean average position (`avg_x`, `avg_y`).
- **Most-used XI:** the formation-constrained XI that maximizes minutes this season, using `select_xi` with minutes in place of rating. Ties go to EA overall.
- Per game: starters, substitutes, data status and how many ideal-XI players started.
- Flag players whose observed Champions League position matches none of their EA positions, in a `role_note` field.
- Keep the pilot's unknown-versus-zero rules.

**Done when:** season totals reconcile with the match sheets. An early substitution, a long substitute appearance and a missing sheet each come out correctly, and validation passes.

### Task 5. Squad subtab: playing time, most-used XI, XI history

**Goal:** show how each club actually uses its squad.

- The XI frame gets an **Ideal / Most used** chip toggle. Most used is the default when usage exists. Each dot shows minutes share, for example with an outline that fills.
- A competition chip selects the usage cohort (league or Champions League). The covered-game count is always shown.
- The squad table gains starts, substitute appearances, minutes and minutes share, plus xG and xA per 90 for domestic competitions only.
- **XI history:** a compact row per game with date, opponent, a starters strip, "ideal players starting n/11", rotation since the previous complete game, and a link to the match page and its heatmap where one exists. Games without data say so.
- Where `role_note` exists, show it beside the player ("plays LB in the Champions League; EA lists RW").

**Done when:** the Task 4 cases display correctly, the competition toggle never pools minutes, and `check_site.py` passes.

### Task 6. EA rating vintages and historical identities

**Goal:** a dated EA rating for as many past player-minutes as possible.

- Collect one EA/FIFA edition per season from FIFA 15 onward, plus in-season updates where a dataset has them. Public datasets often need a Kaggle download; the user downloads anything that needs an account, and the agent never asks for credentials. Record source, edition, update date and file hash per vintage in `data/players/ea/vintages.json`; keep raw files in `.cache/`.
- Link Understat players to EA records within club and season by name, using birth date where the EA file has it. Understat's player ID is stable across clubs, so one link carries through a career; check for contradictions between seasons.
- Commit the link table (`data/players/understat_ea_links.csv`) with method and confidence. Report the share of minutes covered by a rating per league and season.

**Done when:** coverage per league-season is reported, and spot checks of 30 random links are recorded in the PR.

## Wave C

### Task 7. Player impact model (xG plus-minus)

**Goal:** an offline experiment and report, with zero forecast weight.

- For each team-game, xG for = home advantage + team attack + opponent defence + Σ (minutes share × player attacking effect), and xG against likewise with defensive effects. Team terms come from the existing model's strengths before the game.
- Ridge-shrink player effects towards a prior from EA overall and position, with the prior's slope fitted on earlier data. Fit on expanding seasons and evaluate each season with the fit from the seasons before it.
- Report, on later seasons and given actual lineups, team-game xG MAE, RMSE and bias against the team-only model, by league and season. Add learning curves and the 20 largest and 20 most uncertain player effects. A with-or-without split can be shown beside the estimate, never as the estimate.
- Put the model in a new module. Use no dependency beyond the locked environment without the user's approval.

**Done when:** the report states whether lineups improve later-season xG prediction. A negative result completes the task.

## Wave D

### Task 8. Expected-XI forecast adjustment

**Goal:** an evaluated, optional player adjustment to match and standings forecasts.

- **Expected XI:** each player's expected minutes share from recent minutes, decaying with consecutive missed games. Compare it with the simplest variant, the latest XI. Both use only games before the forecast origin, so they replay for every past origin.
- **Adjustment:** the expected lineup's summed impact minus the team's usual lineup's, applied as attack/defence offsets to the Dixon–Coles rates. Season simulations use it for the next few rounds and the usual lineup after that.
- Compare with the current forecast on identical fixtures and origins, with fixed seeds and separate odds/no-odds reporting: match log loss and Brier first, title and top-four metrics as checks. Choose the weight on earlier seasons and check it unchanged on the latest. Integration is an explicit calibration change with a saved artifact. It falls back to the current forecast without lineup data and preserves `--as-of`.

**Done when:** the adjustment ships with a measured gain, or the report shows none.

## Nice-to-haves

- **N1. Injuries and suspensions.** API-Football's free tier (about 100 requests a day) lists injuries and suspensions; check its terms first. Archive dated observations, and set an unavailable player's expected minutes to zero. Show availability on the Squad view first.
- **N2. Confirmed-XI forecasts.** Lineups are announced about an hour before kickoff. Archive them with observation time (ESPN or API-Football), and rerun the match forecast with the confirmed XI, labelled separately from the daily forecast.
- **N3. Boosting.** A pooled LightGBM model of Task 7's remaining xG error from lineup summaries: rating by line, missing regulars, rotation, rest days and observed formation. Kept only if it adds to Task 8 on later seasons.
